# Frontend flow review

## Review scope

Reviewed the requested product flow, onboarding, use-case, API, design-system, and progress documents before changing the frontend. Tested the live authentication adapter and project creation against the local FastAPI service.

## Problems found and fixed

- The sign-in UI used an identity shortcut instead of credentials and did not persist a real backend session.
- Successful registration raced the authenticated-page redirect and skipped first-project setup.
- Project setup contained fixed dates, financial amounts, team email addresses, and fields not accepted by the project-create API.
- Project readiness fell back to a seeded project identifier and assumed every gate response had prerequisite rows.
- The document viewer rendered a fabricated report instead of the stored original document.
- Reconciliation import used local preset rows and sent fields that did not match the backend import schema.
- The contingency ledger rendered invented transfer history despite having no transfer-list endpoint.
- Navigation badges used fixed exception counts rather than live project results.

## Release gaps

- The running local API process returned a legacy invitation URL while the updated API source emits `/auth/invite/{token}`. Restart the API from the current source and rerun browser invitation acceptance before release.
- Invitation acceptance and adaptive onboarding have not been browser-verified for all four invited roles.
- Role-specific home pages and full journeys for CFO, PM, GC, and Investor remain unverified.
- Role-home screenshots, at both requested widths, remain to be captured and reviewed.
- Password reset was tested through request confirmation only; the mailer does not expose a test-delivery link, so completing the token flow in Playwright remains outstanding.
- Email verification is not supported by the backend and the frontend notice cannot complete verification.
- Profile/security/session management and explicit recovery UI for every listed HTTP/network state are not complete.
- Core finance and construction journeys have not all been run end-to-end against live project data.
- Legacy business screens still contain seeded source citations and named reviewers; validate those against real audit/document endpoints before presenting them as live evidence.
- A complete console-error and broken-link audit across every role route remains outstanding.
